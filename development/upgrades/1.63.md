# Playwright 1.63 upgrade review

Tracking: [#394](https://github.com/YusukeIwaki/playwright-ruby-client/issues/394).
Upstream baseline: `v1.62.1`; target: `v1.63.0`, npm commit
`1b025d7e20a026371cd5f98ba0cdce48892737c8`. Ruby gem: `1.62.0` → `1.63.0`.

## Implementation and verification map

| Issue requirement | Implementation | Upstream regression coverage |
|---|---|---|
| Versions and generated API | CLI/gem/CI versions, API JSON, docs, RBS and example mappings | New examples; generation produces identical output on rerun |
| HTTP credentials | Shared Hash/Array normalization for browser context options and APIRequest | `browser_context/credentials_spec.rb`, `browser_context/fetch_spec.rb`, `global_fetch_spec.rb`, `default_browser_context_spec.rb`: legacy Hash, persistent contexts, array, origin, fallback, first match, send policy and Authorization preservation |
| Dialog closure | Context and page events, subscriptions and dispatch | `page/dialog_spec.rb`: accepted, dismissed and automatic dismissal |
| Any-frame locators | Optional positional Page/Frame argument, FrameLocator selector composition and nth guards | `page/locator/any_frame_spec.rb`: final v1.63 suite, including ambiguity, nested scopes, delayed frames, composites and owner/nth restrictions; existing frame-locator examples preserve positional calls |
| Visible locator | Existing visible filter exposed as `Locator#visible` | `page/locator/misc_2_spec.rb` and generated example |
| Action snapshots | Map old booleans and new `ariaSnapshots` / `screenSnapshots` options to the new protocol | `tracing_spec.rb`: default exclusion, PNG/JSON resources and phases |
| Independent request tracing/HAR | Propagate trace directory; reset request tracing on context close | `tracing_spec.rb`, `har_spec.rb`: separate network/actions/HAR, API attribution and Ruby stacks |
| Failed HAR/trace saves | Close context before raising HAR error; stop tracing, discard stack session and clean remote artifact on save failure | `har_spec.rb`, `tracing_spec.rb`: close event, restart and temporary stack-directory cleanup |
| OPFS | Pass `opfs` to storageState; preserve state through existing restore/set APIs | `browser_context/storage_state_spec.rb`: text/binary files, empty directory, default exclusion, path output, restore/replace, persistent WebKit |

The optional positional argument support belongs in the generator. Making the new
`frame_locator` selector a keyword would break existing `frame_locator('iframe')`
callers. Generated wrappers are not edited manually.

The independent request-trace test also found a pre-existing protocol mismatch:
Ruby stacks lacked the required `column` field, so the driver rejected stack
metadata. `Channel` now sends `column: 0`, since Ruby backtraces have no column.

## Deliberate exclusions

- `APIRequestContext#storage_state` was already unimplemented. Its generated `opfs`
  option is reviewed; implementing that missing API is outside this upgrade.
- `Page/Locator.ariaSnapshotJSON` and `BrowserContext.setHTTPCredentials` remain
  JS-only in upstream docs and are excluded by the Python-derived generator.
- Android `swipe` was already missing; the upstream start-point fix has no existing
  Ruby method to modify. Recorder/debugger/isWebView internals and Node test-runner
  features have no matching public Ruby API.
- Reverted `by` locators and tracing screenshot-size options are not introduced;
  superseded `pierceFrames` APIs are replaced by final selectorless frame locators.

## Validation (2026-09-07, macOS, Ruby 4.0.0)

All RSpec commands used `rbenv exec bundle exec rspec` and `CI=1`.
Local runs used `PLAYWRIGHT_CLI_EXECUTABLE_PATH=./node_modules/.bin/playwright-core`.

- Chromium full suite: **1,234 examples, 2 failures, 31 pending** on the first full
  run. Both failures were existing `to_contain_class` error-message expectations:
  v1.63 adds `locator("div")` to the call log. Reproduced with `DEBUG=1`, updated
  the expectations to the final upstream format, then ran all five class matcher
  cases plus the new persistent-context credentials test: **6 examples, 0 failures**.
  The full suite was not repeated after these test-only corrections.
- WebKit focused upgrade/regression suites: **203 examples, 0 failures, 19 pending**,
  including persistent-context OPFS. New API/example smoke checks separately:
  **6 examples, 0 failures**. Pending cases retain browser/API exclusions.
- Strengthened API-request trace-stack assertions separately passed on both
  Chromium and WebKit: **1 example, 0 failures** each. The recorded API call ID
  resolves to this Ruby spec's stack, including the required zero column.
- Remote Chromium (`playwright-core run-server`): API/example checks
  **17 examples, 0 failures**; action snapshots and failed-save recovery
  **6 examples, 0 failures, 1 pending**. The pending check requires a local stack
  session, which the thin remote connection does not have.
- Optional Firefox smoke run: all 6 cases were blocked before test execution by
  Firefox r1543 reporting `Could not find profile folder`. Reproduced with
  `DEBUG=1` and with the upstream Node client, including a task-local temporary
  directory. Firefox behavior remains unverified on this host.
- Ruby 2.4 grammar parsing passed for the example spec, example mappings, and all
  12 changed library files. Ruby 2.4 runtime and the complete CI Ruby-version
  matrix were not available locally.
- Final API generation reproduced identical API/docs/unimplemented-example
  checksums. No new entries remain in `development/unimplemented_examples.md`.
  `git diff --check` passed.

The tests were ported before handwritten implementation. The initial focused
failures were rerun with `DEBUG=1`; protocol logs identified the credentials-array,
optional positional-argument and missing stack-column incompatibilities.
