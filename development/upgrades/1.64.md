# Playwright 1.64.0 upstream review

Source: [v1.63.0...v1.64.0](https://github.com/microsoft/playwright/compare/v1.63.0...v1.64.0). No 1.64 language-port tracking issue was available at review time. The table follows upstream commit order and includes PRs touching client, protocol, API docs, injected scripts or library/page/browser-context/assertion tests. Release cherry-picks are reviewed at the shipped commit, `606ecd8b34bac100db32561b6278ffd76e5eb3cd`.

Server and injected-script fixes ship in the 1.64 driver. Existing Ruby integrations already delegate these behaviors to that driver; only changes to the Ruby API, serialization or client logic require a port. The Node test runner, trace viewer, Android and BiDi are outside the Ruby API.

Ruby uses Python as its upstream SDKLanguage because upstream does not support Ruby code generation. Locator#to_s now returns the driver-generated Python locator text (or a custom description); normalized locators cache this text and can render it after the page is closed. Ordinary locators keep the existing selector fallback if LocalUtils is unavailable in remote mode.

APIRequestContext#storage_state remains an existing unsupported API. The addCookies test verifies the same cookie-jar contents through the new public cookies API. The Node test-runner screen forwarding change (#42681) does not change the Ruby client's device descriptors.

The revised Credentials example (`example_a1fe...`, replacing `example_4418...`) comes from #43041. The new normalize example (`example_0b5d...`) comes from #43175, within (`example_622c...`) from #42887, get_by_ref (`example_aedd...`) from #43055, add_cookies (`example_c660...`) from #43032 and clear_cookies (`example_7db9...`) from #43052.

## Verification

- Full Chromium suite on Ruby 4.0: **1,290 examples, 0 failures, 29 pending**.
  Run with `CI=1 PLAYWRIGHT_CLI_EXECUTABLE_PATH=./node_modules/.bin/playwright-core rbenv exec bundle exec rspec`.
- WebKit focused API and regression coverage: **134 examples, 0 failures, 1 pending**.
  Covers request cookies, locator composition/formatting/normalization, shadow content,
  signCount, video fps, screencast styles/cursor, tracing disposal/stacks, recorder,
  network error code, new examples and hidden iframe visibility. The pending iframe
  case retains its existing upstream-behavior exclusion.
- Remote Chromium (`playwright-core run-server`) new examples: **3 examples, 0 failures**.
  Includes normalized refs, relative columns and browser-owned request cookies.
- Optional Firefox WebMCP verification was blocked before test execution: Firefox
  r1555 exits with `Could not find profile folder`. Reproduced with `DEBUG=1` and
  with the upstream Node client, including `TMPDIR=/tmp`. Firefox behavior remains
  unverified on this host; the specs retain upstream Firefox feature exclusions.
- Ruby 2.4 grammar parsing passed for all 14 changed handwritten library files,
  the example mappings and the example spec. Ruby 2.4 runtime and the complete CI
  Ruby-version matrix were not available locally.
- Re-fetching API JSON from the exact npm gitHead and clean regeneration reproduced
  identical API/docs/wrapper/RBS/unimplemented-example checksums. All six new or
  revised example mappings are handled; no new unimplemented examples remain.
- `git diff --check` passed. Focused failures were rerun with `DEBUG=1` before
  correcting locator chaining, normalized-code expectations and string trace-ID
  matching.

### CI follow-up

- All 12 Chromium/WebKit integration jobs failed because the recorder regression
  opened a headed Inspector without an X server. Use the existing
  `playwright_under_test` fixture so the Inspector runs headless, matching upstream
  test behavior while retaining the recorder assertions.
- Clock specs now wait for Ruby binding callbacks after a clock error and confirm
  that worker-thread evaluations have registered their timers before advancing
  the clock. This removes the callback-delivery and timer-registration races seen
  in the Ruby 2.7 and 3.4 CI jobs.
- The cursor movement spec polls for changed coordinates, matching upstream's
  assertion. Visibility alone no longer waits for movement because the 1.64 cursor
  persists between actions; this caused the WebKit/Ruby 3.3 failure.
- The subsequent CI run exposed a Chromium/Ruby 3.2 trace-buffer race: stopping
  immediately after navigation sometimes produced no screenshot events. Port
  upstream's `rafraf(page, 100)` wait before stopping the trace so Chromium has
  rendered screenshot frames.
- Reproduced the Inspector failure with `DEBUG=1` in an Ubuntu Noble/Ruby 3.2
  container without an X server: **1 example, 1 failure** before the fix.
- After the fixes, all three affected spec files passed with `DEBUG=1`:
  **63 examples, 0 failures** each on Linux Chromium, Linux WebKit and macOS
  Chromium/Ruby 4.0.
- The trace-buffer failure also reproduced with `DEBUG=1` on Linux before its
  fix: **1 example, 1 failure**. After adding the upstream rendering wait, the full
  tracing spec passed with **22 examples, 0 failures** on both Linux Ruby 3.2 and
  macOS Ruby 4.0.
