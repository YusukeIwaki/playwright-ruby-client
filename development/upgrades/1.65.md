# Playwright 1.65.1 upstream review

Source: [v1.64.0...v1.65.1](https://github.com/microsoft/playwright/compare/v1.64.0...v1.65.1). No 1.65 language-port tracking issue was available at review time; the playwright-python roll PRs ([#3327](https://github.com/microsoft/playwright-python/pull/3327), [#3346](https://github.com/microsoft/playwright-python/pull/3346)) ported no client changes. The table follows upstream commit order and includes PRs touching client, protocol, API docs, injected scripts, server code or library/page tests. Release cherry-picks are reviewed at the shipped commit, `bbd948344ea9a60bf1e6f125c02ca99b2b51593b`.

The headline 1.65 features (Bun, the `failures` reporter, `onlyFailures`, test locks) belong to the Node test runner and are outside the Ruby API. Server and injected-script fixes ship in the 1.65 driver. Existing Ruby integrations already delegate these behaviors to that driver; changes to the Ruby API, serialization or client logic require an implementation port. Driver-side fixes can also require RSpec regression coverage.

Generated signature changes: `CDPSession#send_message` gains `timeout:`. `Frame#hidden?` and `Frame#visible?` no longer accept the ignored `timeout:` option, because upstream removed it from the Python signature that Ruby follows (#43372); `Page#hidden?` and `Page#visible?` are unchanged. Other differences are keyword-argument order and documentation text.

Not ported:

- `unroute_all(behavior:)` (#43889). Ruby accepts the option but does not implement it; the existing pending spec in `page/route_spec.rb` records this. The fix applies only to `behavior: 'wait'` and is deferred to a separate change.
- `supportsLoneSurrogates` (#43548). Ruby's JSON parser rejects lone surrogates, so the client does not declare support and the driver replaces them with U+FFFD.
- Upstream cases that need Node-only facilities: the `__testHookLookup` cookie test, `NaN`/`Infinity` clock ticks (not serializable from Ruby), `URLSearchParams` and query strings without a leading `?`, `data: null`, and the `signal` option.

## Verification

- Baseline before porting, 1.65.1 driver with the 1.64 client: **1,290 examples, 8 failures, 29 pending**.
  The failures were the generated `CDPSession#send_message(timeout:)` wrapper calling the old
  implementation (5), host-only cookie matching, the outline shorthand order and the new Chromium
  WebMCP error text.
- Full Chromium suite on Ruby 4.0: **1,330 examples, 0 failures, 29 pending**.
  Run with `CI=1 PLAYWRIGHT_CLI_EXECUTABLE_PATH=./node_modules/.bin/playwright-core rbenv exec bundle exec rspec`.
- WebKit, all changed or added spec files plus the example spec: **310 examples, 0 failures, 11 pending**.
- The JSON content-type and `har.ZIP` specs fail without the library changes (5 failures) and pass with them.
- Ruby 2.4.10 grammar parsing passed for the four changed library files, the example mappings and
  the example spec. Ruby 2.4 runtime and the complete CI Ruby-version matrix were not run locally.
- Re-fetching API JSON from the exact npm gitHead and clean regeneration reproduced identical
  API/docs/wrapper/RBS/unimplemented-example checksums. No new unimplemented examples.
- `git diff --check` passed.
- Firefox and the remote-server (`run-server`) configuration were not run locally.

### Review follow-up

Ported six additional examples and extended one existing example from the shipped v1.65.1 tests,
preserving the upstream test names, issue annotations, operation order and assertions:

- `page/clock_spec.rb`: CK-045, CK-046 and CK-220 cover paused clock replay across navigation,
  init-script time reads, `performance.now()` and timers registered during page load.
- `page/aria_snapshot_spec.rb`: AR-008 and AR-009 cover closed details and unassigned slot text.
  AR-031 now includes the complete release HTML and snapshot for `-`, `~`, `.inf` and `.NaN`.
  All three check both snapshot output and the snapshot matcher; AR-009 also checks the role locator.
- `browser_context/har_spec.rb`: HA-114 corrupts both ZIP entry names from `aa/x.har` to
  `../x.har` and checks the `invalid relative path: ../x.har` rejection.

Validation on Ruby 4.0 with the 1.65.1 driver, using `rbenv exec bundle exec rspec`:

- The seven changed examples on Chromium: **7 examples, 0 failures**.
- All three affected spec files on Chromium: **102 examples, 0 failures**.
- All three affected spec files on WebKit: **102 examples, 0 failures**.
